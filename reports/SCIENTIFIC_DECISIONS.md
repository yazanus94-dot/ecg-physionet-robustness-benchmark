# Scientific decisions and stale-result register — ECG-ROBUST

This report records decisions that affect interpretation of the benchmark. It does **not**
change any committed result. No dataset was downloaded and no experiment was rerun as part of
this audit.

## 1. Feature-selection leakage (fixed in code, results stale)

`scripts/feature_ablation.py::ablation_columns` previously ranked features with a RandomForest
fit on all beats; the same held-out fold then influenced which columns it was scored on. The
code now refits selection on each training fold only, with a regression test that permutes
validation labels and verifies the selected columns are unchanged.

- **Affected artefact:** `reports/results/feature_ablation.csv` (and any figure derived from it).
- **Status:** **STALE** — generated by the previous, leaky implementation.
- **Regeneration (requires the locally present, licensed MITDB/NSTDB data):**
  `python scripts/feature_ablation.py`. Do not run it without the authorized dataset.

## 2. Model selection on evaluation folds (open decision)

`pipeline.py` selects `best_model = cv_means.idxmax()` on the same 5 folds whose out-of-fold
table is reported. That is a selection diagnostic, not an unbiased final comparison; the
winner's curse can inflate the selected model's apparent performance.

Options:
1. **Nested CV (preferred for a new unbiased estimate):** outer patient-grouped folds for
   evaluation, inner group-aware folds for model choice. Compute cost ~5x. Would produce new
   numbers; no such result is claimed here.
2. **Keep the current OOF comparison but label it explicitly as model selection** and report
   all models without a "best" headline. This preserves history and is honest but not an
   unbiased comparison.

Decision deferred: it changes reported results and the experiment's scope. Until then, the
current table must be read as selection diagnostics only.

## 3. NSTDB noise realizations (open decision)

The eight realizations currently come from `nstdb_records[:8]` — stress-test signals derived
from patients 118/119 that contain ECG morphology plus noise (e.g. `118e00` header: created
from record 118 and `em`). The pure-noise control records are `bw`, `em`, `ma`.

- **Current experiment measures:** robustness to realistic *contaminated ECG* signals whose
  QRS morphology overlaps the training patients; it is **not** a pure-noise robustness test.
- **Pure-noise alternative:** use only `bw`/`em`/`ma`; measures robustness to stationary
  electrode/motion noise without competing QRS structure. It changes the SNR sweep headline
  and makes existing `noise_results.csv` / `nstdb_evaluation.csv` stale.
- Neither represents all clinical noise; both remain synthetic-mixture stress tests.
- Records without valid annotations must not be given invented ground-truth labels.

Decision deferred: switching changes reported metrics and research interpretation.

## 4. Confidence intervals (limitation)

Reported metrics are fold means/standard deviations, not confidence intervals. Any future
interval must resample **recordings/patients**, not individual beats (beats are correlated
within a record). With 5 recording-level folds, intervals will be wide; report the resampling
unit, number of bootstrap replicates, seed and the small-sample limitation. No CI is claimed
in the current reports.

## 5. Configuration (fixed in code)

`configs/default.yaml` is now an optional, validated override file read via
`ECG_ROBUST_CONFIG`; changing `n_splits` or `random_state` demonstrably changes the pipeline's
 CV setup (tested). With no environment variable, the historical constants are used, so
committed results remain reproducible. The subject grouping 201/202 remains in code
(`splits.make_groups`) because it is a property of the database, not a tunable parameter.
